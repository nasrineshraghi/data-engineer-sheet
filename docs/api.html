APIs for Data Engineers

How pipelines pull, push, and design HTTP APIs — contracts, retries, and incremental extracts.

REST API

HTTP API that manipulates resources with methods like GET, POST, PUT/PATCH, DELETE and status codes.

Why: Most SaaS extracts and internal services speak REST; pipelines are HTTP clients first.

Example: `GET /v1/orders?updated_since=2024-01-01` → JSON list of orders.

Endpoint / Resource

A URL path that represents a collection or item (`/customers`, `/customers/{id}`).

Why: Your extract grain and join keys usually follow resource design.

Example: `/patients/{id}/labs` returns lab results for one patient.

Request / Response

Client sends a request (method, URL, headers, body); server returns a response (status, headers, body).

Why: Logging only the body loses status and rate-limit headers you need to debug.

Example: Request `Authorization: Bearer …` → Response `200` + JSON payload.

JSON / Payload Schema

Structured body format (usually JSON) with an agreed shape for fields and types.

Why: Schema drift breaks pipelines; optional fields become required without notice.

Example: `{ "order_id": "O-1", "total_cents": 1999, "currency": "USD" }`

Status Codes

Numeric HTTP outcomes: 2xx OK, 3xx redirect, 4xx client error, 5xx server error.

Why: Retry logic must distinguish “bad request” from “try again.”

Example: `429 Too Many Requests` → back off; `401` → refresh auth, don’t hammer.

Authentication vs Authorization

Authentication = who you are; authorization = what you’re allowed to do.

Why: A valid token can still lack scope to read the dataset you need.

Example: Service authenticates with OAuth client credentials but isn’t authorized for `/admin/exports`.

API Key

Static secret sent in a header or query param to identify the calling app.

Why: Simple but easy to leak in logs, notebooks, and git.

Example: Header `X-API-Key: sk_live_…`

OAuth 2.0 / Bearer Token

Delegated auth where the client gets a short-lived access token (often refreshable).

Why: Most modern SaaS APIs require token refresh in long-running pipelines.

Example: Client credentials → `access_token` → `Authorization: Bearer <token>`.

Pagination

Splitting large result sets across pages (offset/limit, cursor/token, or page numbers).

Why: Full extracts die without pagination; naive offset pages drift under concurrent writes.

Example: `GET /events?cursor=eyJpZCI6MTAwfQ&limit=500`

Rate Limiting

Server caps how many requests you can make per window (per key, IP, or tenant).

Why: Ignoring limits causes 429s, bans, and incomplete loads.

Example: 100 req/min; response headers `X-RateLimit-Remaining: 0`, `Retry-After: 30`.

Idempotency Key

Client-supplied key so retries of the same write are applied once.

Why: Network timeouts cause duplicate POSTs without idempotency.

Example: Header `Idempotency-Key: load-2024-01-01-batch-7` on `POST /charges`.

Webhook

Server pushes an HTTP callback to your URL when an event happens (vs you polling).

Why: Near-real-time ingest without constant polling cost.

Example: Stripe sends `POST /hooks/stripe` with `invoice.paid` payload.

Polling vs Event-Driven

Polling periodically GETs for changes; event-driven consumes webhooks/streams as events arrive.

Why: Polling is simple but laggy/expensive; events need reliable endpoints.

Example: Poll `updated_since` every 5 minutes vs webhook on `order.updated`.

API Contract / OpenAPI

Documented agreement on paths, params, schemas, and errors (often OpenAPI/Swagger).

Why: Contracts let you generate clients and catch breaking changes in CI.

Example: OpenAPI spec declares `Order.total_cents` as integer required.

Versioning

Evolving an API without breaking clients (`/v1`, `/v2`, or header versions).

Why: Unversioned breaking changes silently empty or corrupt warehouses.

Example: `/v1/orders` keeps old shape while `/v2/orders` renames fields.

Timeout / Retry / Backoff

Client gives up after N ms; retries failed calls with increasing delay (and jitter).

Why: Aggressive retries amplify outages; no retries drop data.

Example: Timeout 30s; retry 5xx/429 with exponential backoff + jitter.

Synchronous vs Asynchronous API

Sync returns the final result in one response; async accepts work and returns a job id to poll or webhook later.

Why: Big exports are often async — treating them as sync causes timeouts.

Example: `POST /exports` → `202` + `job_id` → poll `/exports/{job_id}` until `download_url`.

GraphQL (Basics)

Query language API where the client asks for exact fields in one request (vs many REST round-trips).

Why: Flexible reads; easy to over-fetch or hit cost/complexity limits.

Example: Query `{ order(id:"O-1") { id total items { sku qty } } }`

gRPC / Protobuf (Basics)

Binary RPC framework using Protocol Buffers — common for internal low-latency services.

Why: Faster than JSON REST inside the datacenter; schemas are strongly typed.

Example: `GetOrder(OrderRequest) returns (Order)` over HTTP/2.

Change Data via API (Incremental Extract)

Pull only new/changed rows using cursors, `updated_at` filters, or event APIs.

Why: Full dumps don’t scale; incremental needs trustworthy watermarks.

Example: `GET /objects?updated_after={watermark}&sort=updated_at`

SLA / Quotas

Provider promises (latency, uptime) and hard caps (rows/day, concurrent calls).

Why: Pipeline design must fit quotas or fail mid-load.

Example: Free tier 10k calls/day; enterprise 100 concurrent connections.
