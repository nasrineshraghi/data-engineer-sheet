Prod playbook

Start from what you see in production, not from the topic list.

See: KPI / revenue suddenly wrong after a join or backfill

Do: Declare grain on both sides. Aggregate to the reporting grain before summing. Prefer overwrite/MERGE for backfills.

Concepts: Grain, Idempotency, Additive Facts

Habit: Never sum a measure until you know what one row means.

See: Job failed, was rerun, now rows are duplicated

Do: Make the write rerunnable: partition overwrite, MERGE on business keys, or deterministic upserts.

Concepts: Idempotency, At Least Once, Checkpointing

Habit: Design every pipeline as if it will be retried tomorrow.

See: One Spark task runs forever; the rest finished

Do: Open Spark UI → slow stage → shuffle read. Check for a hot key; salt / AQE skew join / pre-aggregate.

Concepts: Data Skew, Shuffle, Salting

Habit: Debug stages and bytes, not just wall-clock time.

See: Query reads years of data for one day

Do: Filter on partition columns (often date). Push filters into the scan. Avoid transforming before filtering.

Concepts: Partition Pruning, Predicate Pushdown, Scan Pruning / Partitioning

Habit: Filter early. Always.

See: Pipeline is green but dashboards look stale

Do: Track freshness (max event time / partition arrival). Alert on SLA, not only task success.

Concepts: Freshness, Observability, SLA / Callback

Habit: Success ≠ useful data.

See: Lake / table queries get slower every week

Do: Check file counts and sizes. Compact small files; target healthy file sizes.

Concepts: Small File Problem, Compaction, File Size Tuning

Habit: Ingest shape becomes query cost.

See: Warehouse / cloud bill spiked with same dashboards

Do: Find heavy queries: SELECT *, missing partition filters, huge shuffles. Attribute cost to owners.

Concepts: Column Pruning, Scan Pruning / Partitioning, Cost Observability

Habit: Bytes scanned are the bill.

See: Hourly metrics keep changing hours later

Do: Use event time + watermarks. Document how late data is handled (update vs ignore).

Concepts: Event Time, Watermarks, Late Data

Habit: Processing time lies; event time is the business clock.

See: Producer changed a field; overnight jobs failed

Do: Schema registry compatibility + enforce-on-write + data contracts before fan-out.

Concepts: Data Contracts, Schema Enforcement, Schema Registry

Habit: Prevent breaking changes at the boundary.

See: Historical report shows today’s attributes, not past ones

Do: SCD Type 2 (or equivalent) with effective dates; join on the version valid at event time.

Concepts: SCD Type 2, Surrogate Key, Effective Dating

Habit: Dimensions change; facts must remember the past.

See: Join or group-by much slower than expected

Do: Check distinct counts (cardinality). Wrong NDV → bad join strategy. Broadcast small side when safe.

Concepts: Cardinality, Shuffle, Broadcast Join

Habit: Know which side is small before you join.

See: Spark job ‘does nothing’ then suddenly runs forever at write/count

Do: Remember lazy evaluation: actions trigger jobs. Inspect the plan before the expensive action.

Concepts: Lazy Evaluation, Job → Stage → Task, Catalyst Optimizer

Habit: Read the plan; don’t wait for the surprise.

See: Antibiotic timing / adherence metrics look wrong vs nursing charts

Do: Confirm whether the metric should use order, dispense, or administration time. Prefer MAR administered_at for inpatient dosing.

Concepts: Order → Dispense → Administration Chain, Medication Administration (MAR), Clinical Event Time vs System Time

Habit: Name the medication stage before you write the SQL.

See: Lab trends jump or ETL fails casting result values

Do: Split numeric vs text results; group by LOINC + unit (UCUM); convert before charting. Use collection time for physiology.

Concepts: Units of Measure (UCUM), Quantitative vs Qualitative Results, LOINC

Habit: Same LOINC with mixed units is not one series.

See: SaaS extract fails with 429s or incomplete pages

Do: Respect Retry-After, lower concurrency, use cursor pagination, and budget calls against quotas.

Concepts: Rate Limiting, Pagination, Timeout / Retry / Backoff

Habit: Throughput is limited by the API, not your cluster size.

See: Webhook-fed table has duplicate events after provider retries

Do: Upsert on event id, verify signatures, and run a nightly reconcile poll.

Concepts: Webhook, Idempotency Key, Polling vs Event-Driven

Habit: At-least-once delivery needs idempotent handlers.

See: Lake queries slow; driver struggles listing files

Do: Check file counts/sizes. Compact small Parquet files; target ~128MB–1GB. Fix streaming small-file write pattern.

Concepts: File Size Tuning, Parquet, Delta / Iceberg / Hudi Data Files

Habit: Table formats manage files — you still owe them healthy Parquet sizes.

See: One executor works; the rest of the cluster is idle on ingest

Do: Avoid non-splittable huge .gz CSV. Convert to Parquet/ORC; use splittable compression.

Concepts: Splittable File, Snappy / ZSTD / Gzip, Parquet

Habit: If it isn't splittable, you don't have parallelism.

See: Team debates Data Vault vs star schema vs one big table

Do: Separate layers: integrate multi-source history in Vault/3NF; serve shared KPIs as star marts; flatten to OBT only for a single consumer (BI extract or ML features).

Concepts: Modeling Pattern Choice, Data Vault, Star Schema, One Big Table (OBT)

Habit: Pattern follows the layer and the consumer — not a single company-wide religion.

See: Hourly cron still running when the next hour fires; duplicates or locks

Do: Prevent overlap (flock / max_active_runs=1), make writes idempotent, or move to an orchestrator with sensors.

Concepts: Overlapping Cron Runs, Idempotency, Cron vs Orchestrator

Habit: A schedule is a start signal — not a guarantee the previous run finished.

See: Partition dates off by one day after a DST change or UTC vs local schedule

Do: Run schedules in UTC; derive business-local dates in code; document the clock the cron uses.

Concepts: Cron Timezone Pitfalls, Cron Expression, Execution Date / Data Interval

Habit: Never assume the server’s local midnight is the business day.
